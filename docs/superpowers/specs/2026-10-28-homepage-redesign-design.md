# 首页 UI 改版设计

日期：2026-10-28
定稿视觉稿：[2026-10-28-homepage-redesign-mockup.html](2026-10-28-homepage-redesign-mockup.html)（直接用浏览器打开）

## 为什么改

现在的 remotecn.com 首页只有一个标题区和一个职位列表，视觉单调。目标是让首页更有"科技感"、更有记忆点，整体参考 [lennysjobs.com](https://www.lennysjobs.com/)：浅暖色、动态背景、居中大标题、分段搜索栏、白底职位卡片。

我们的特点和 Lenny 不同：职位多来自 V2EX、电鸭等社区的中小团队，没有大厂 logo 可用，所以首屏背景用**职位分类 + 技术关键词**漂移，而不是公司 logo 墙。

## 目标

- 首页换成定稿视觉稿的样子：桃色渐变首屏、漂移标签背景、分段搜索栏、左侧筛选栏 + 右侧职位卡片、"加载更多"、极简页脚。
- 字号、字重、颜色层级对齐 lennysjobs，次要信息弱化（见"文字规范"）。
- 统一全站的新主题：配色、字体、Logo、顶部导航、页脚也用到详情页和关于/联系/隐私页。
- 从分页改成"加载更多"，并保证返回列表时位置不丢。

## 非目标

- 不接入新数据源（另行处理）。
- 不做薪资展示（数据库没有薪资字段）。
- 不做"发布职位""订阅更新"功能，页面上也不放这两个按钮。
- 不做深色模式。
- 详情页、关于页等内页只换主题（颜色、字体、导航、页脚），不重新设计布局。

## 反目标（做到了也算失败）

- 首屏背景动画干扰阅读：标题、副标题、搜索栏必须清晰可读，背景标签在中间区域要淡出。
- 首屏过高：桌面端（1280 宽）首屏背景区高度控制在约 315px，和 Lenny 的 311px 相当，第一屏能直接看到职位列表。
- 手机端出现横向滚动（视觉稿迭代中出现过，务必避免）。
- 中文字体拖慢首屏：中文 Web 字体必须子集化或按需加载，不能整包下载。
- SEO 退化：首页首批职位仍然服务端渲染，职位详情页的收录方式（sitemap）不变。

### Logo

小写字标 `remote`，后面跟一个橙色贴纸 `cn`：橙底、2px 黑边、圆角 8px、底部 3px 黑色实心阴影、逆时针倾斜 4°，悬停时转到 +3°。Favicon 和 OG 图同步换成这个风格（贴纸 `cn` 单独做 favicon）。

### 按钮

主按钮：橙底、2px 黑边、圆角 10px、底部 3px 黑色实心阴影；悬停下沉 1px、阴影变 2px。

## 页面结构

### 顶部导航（全站共用）

- 吸顶，桃色半透明 + 毛玻璃，底部一条极淡分隔线，高 64px。
- 左：Logo；右：职位 · 关于 · 联系我们。手机端也显示这三个链接。
- 没有其他按钮。

### 首屏

- 桃色到米白的竖向渐变背景。
- 背景：6 行标签斜着（-3°）水平漂移，相邻行方向相反、速度略有不同（70–115 秒一圈）。
  - 分类标签：粗体 + emoji + 职位数，如"🤖 AI/机器学习 64"。
  - 关键词标签：等宽字体，如 React、Go、LLM。
  - 中间区域用径向渐变遮罩淡出，保证文字可读。
  - 鼠标悬停时整体暂停，单个标签浮起变白。点击标签直接按该分类或关键词筛选列表。
  - 遵守 `prefers-reduced-motion`：开启时不漂移。
- 前景居中：
  - 大标题"为中国开发者找远程工作"（单行）。
  - 副标题"聚合全网远程开发岗位，AI 自动分类。前端、后端、AI、Web3，一处搜完。"
  - 分段搜索栏：白底、2px 黑边、圆角 22px、无阴影；四段为关键词 / 职位方向 / 地域 / 工作性质，右侧橙色"搜索 →"按钮。手机端竖排。
  - 搜索栏下方一行：绿点徽章"每小时更新" + "共 N 个在招职位"。

### 列表区

- 桌面：左侧 250px 吸顶筛选栏 + 右侧卡片列表；手机：筛选栏变成一行可横向滑动的分类标签。
- 筛选栏：
  - 顶部"N 个职位"和"✕ 清除筛选"。
  - 职位方向：全部 + 各分类，带数量，选中项白底黑描边。
  - 地域、工作性质两组单选（选项见"设计时做的决定"第 1 条）。
- 列表头：左"排序：最新发布"，右"最近同步 X 分钟前"。
- 职位卡片：白底、1px 边框、圆角 18px；左侧分类 emoji 图标；标题（后面不带箭头）、公司名（有才显示）、两行描述、"地域 · 性质"、分类标签 + 技术标签；右上角发布时间（24 小时内绿色带圆点），右下角"via 来源"。悬停时黑边 + 底部 4px 实心阴影 + 上浮 2px。
- 空结果、加载中、出错三种状态要有对应样式，沿用现有文案。

### 加载更多

- 每次加载 20 条（现在是 10 条分页）。
- 按钮上方：细进度条（已加载 / 总数）+ "已显示 20 / 417 个职位"。按钮为橙色主按钮"加载更多职位"。
- 全部加载完后，按钮换成"已经到底了"的文字。
- 把已加载到第几页和当前筛选条件写进网址（如 `?category=ai&page=3`）。从详情页返回时恢复已加载的列表和滚动位置；直接打开带参数的网址时，服务端渲染对应的筛选结果。
- 删除现有的分页组件。

### 页脚（全站共用）

一行居中小字："© 2025–2026 remotecn · 隐私政策"，12px muted，上方一条细分隔线，整体高约 47px。

## 需要的数据

视觉稿里有几处数据现在的接口拿不到，需要后端加一个统计接口（例如 `GET /api/jobs/stats`）：

- 每个分类的在招职位数（首屏标签、筛选栏数量），全站总数，不随筛选变化。
- 地域、工作性质各选项的数量。
- 在招职位总数。
- 最近一次同步时间（"最近同步 X 分钟前"）。

技术关键词标签（React、Go 等）的列表和来源由实现方决定，见下文。

## 已有约束

- Next.js 14 App Router + Tailwind + Radix，主题色走 `globals.css` 里的 CSS 变量。
- 首页首批数据通过 `getServerJobs()` 服务端渲染，失败时返回空列表不崩。
- 分类是数组，一个职位可以属于 1–3 个分类。
- UI 语言为中文。

## 设计时做的决定（可推翻）

以下几点视觉稿没有说清楚，我按"尽量不改后端行为"的原则定了，产品负责人可以推翻：

1. **地域、工作性质的选项沿用现有取值**。地域：不限 / 🌍 全球（`worldwide`）/ 🇨🇳 中国（`CN`），和现在的 `COMMON_REGIONS` 一样，后端仍然精确匹配 `regionLimit`。工作性质：不限 / 全职 / 兼职，单选。视觉稿里"全球远程 / 地区限制""全职 / 兼职"这类写法只是示意。搜索栏里的地域、工作性质下拉也用同一套选项。
2. **筛选栏以本文档为准，不用视觉稿里的"快速筛选"**。去掉"只看 7 天内"和"只看全职"两个开关，换成地域、工作性质两组单选。后端没有日期筛选，这次不加。
3. **数量显示全站总数，不跟着当前筛选变**。首屏标签和筛选栏共用一次统计接口的结果，可以缓存（例如 5 分钟）。
4. **点击背景里的技术关键词 = 用这个词做关键词搜索**，同时把关键词搜索的范围从"只搜标题"扩大到"标题或技术标签"。标签匹配不区分大小写、需要整词相等（搜 React 不会命中 Reactor，也能命中标签是 react 的职位）。搜索框里会显示这个关键词，和手动输入的效果一样。
5. **职位卡片仍然跳转站内详情页 `/jobs/:id`**，和现在一样，保留首页到详情页的可爬链接。卡片标题后面不放箭头（视觉稿里的 ↗ 去掉），整张卡片可点击。"从详情页返回时恢复列表和滚动位置"按这个前提实现。

## 实现方自行决定

- 统计接口的具体路径、返回结构、缓存策略。
- 技术关键词标签的来源：写死一份热门关键词，或从职位 `tags` 统计得出。
- 中文字体子集化的方式（`next/font` 配置、自托管子集等）。
- 组件怎么拆分，以及是否保留 Radix Select。
- 内页（详情、关于、联系、隐私）具体怎么套用新主题，只要配色、字体、导航、页脚一致即可。
